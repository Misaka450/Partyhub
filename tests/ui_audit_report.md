# PartyHub UI 视觉自动化测试报告（人工复核版）

> 生成时间：2026-08-28 ｜ 被测地址：http://127.0.0.1:8080 ｜ 测试方式：无头浏览器 + Chrome DevTools Protocol 真机渲染

---

## ⚡ 二次逐图复核修正（2026-08-28）

> 初版报告把移动端问题定性为"个别缺陷"，**低估了严重程度**。逐张复查全部 24 张移动端截图 + 审计 style.css 后修正结论：
>
> **PartyHub 基本没有做响应式自适应。** 4281 行 CSS 中仅 5 条 `@media`，其中面向移动端的只有 2 条（`max-width:768px` 改游戏磁贴列数、`max-width:600px` 改席位网格），其余 3 条是 `min-width` 桌面增强。除这两个网格外，**顶栏、聊天栏、全部 12 款游戏舞台的内部布局均无任何移动端断点**。
>
> 因此下文"缺陷 1-5"应合并理解为**同一个根因**：缺少移动端媒体查询体系。逐游戏截图实证：
>
> | 游戏 | 移动端(≤390px)截图实证 |
> |---|---|
> | 全部场景 | 顶栏房间号 pill + 游戏标签占掉 ~85% 宽度，轮次/人数/退出/邀请/音效/主题全部被推出屏幕 |
> | 大厅 | 「邀请好友」「5人已入席」按钮文字逐字竖排堆叠 |
> | 决战24点 | 「退格」按钮文字竖排（退/格） |
> | 词汇炸弹 | 「传弹」按钮文字竖排（传/弹）；炸弹卡上方大片空白 |
> | 拆弹轮盘赌 | 「白线」引线卡：白字浅底，文字几乎不可见（真实对比度缺陷，非误报） |
> | 瞬间数羊 | 深绿底上深灰提示文字，可读性差 |
> | UNO | 底部手牌严重挤压重叠、两侧被裁切 |
> | 阿瓦隆 | 任务队大小行(2人/3人/3人*)贴边挤压；「轮次任务」标签被裁成「轮次任」 |
> | 你画我猜 / 3D数方块 / 切披萨 / 盲压 / 卧底 | 主体尚可，但均共享顶栏溢出问题；画板/输入区未针对小屏优化留白 |
>
> **修复方向应为体系性的**：建立移动端断点规范（顶栏折叠/收纳次要控件、房间号省略、按钮 nowrap、各舞台弹性布局、UNO 手牌扇形缩放、白线/深底文字配色修正），而非逐个补丁。

## 一、测试概述

本报告对 PartyHub 的 **12 款聚会游戏** 及 **登录页、游戏大厅** 进行了全面的无头浏览器 UI 视觉自动化巡检，系统性检测以下视觉呈现问题：

- 界面布局错乱 / 元素错位 / 元素越界
- 字体显示异常（字号过小、文字裁切）
- 颜色渲染错误（文字与背景对比度不足）
- 响应式设计失效（多断点布局）
- 交互元素功能异常（点击区过小、不可点击）
- JS 运行时错误与资源加载失败

### 测试覆盖矩阵

| 维度 | 覆盖范围 |
|---|---|
| 浏览器 | Microsoft Edge 151（Blink 内核，全量 5 断点）、Google Chrome 151（Blink 内核，抽样 2 断点） |
| 屏幕分辨率 | 360×780（手机小）、390×844（手机）、768×1024（平板）、1280×800（笔记本）、1920×1080（桌面） |
| 页面场景 | 登录页 + 游戏大厅 + 12 款游戏开局舞台（5 人真实房间驱动） |
| 审计截图 | **98 张**（`tests/ui_audit_screens/`），命名 `<浏览器>_<分辨率>_<场景>.png` |

> ⚠️ **内核覆盖限制说明**：本机仅安装了 Edge 与 Chrome，二者同为 Chromium/Blink 内核。**未能覆盖 Firefox(Gecko) 与 Safari(WebKit) 内核**，因此无法检测跨内核渲染引擎差异（如 flex 布局解析、emoji 字体回退、`backdrop-filter` 兼容性等 Blink 内部一致但跨内核可能不同的问题）。如需完整跨内核覆盖，需额外安装 Firefox 或使用云端真机矩阵（如 BrowserStack）。

## 三、真实缺陷明细

### 🟠 缺陷 1（High）：移动端顶栏右侧控件溢出视口、无法点击

- **问题**：在 ≤390px 窄屏下，`.game-header` 顶栏左侧"房间号 pill + 游戏标签"占据过多宽度，导致右侧的 **轮次标签、人数按钮、退出房间、邀请好友、音效切换、主题切换、计时器** 等控件被推出视口右边界，**既看不见也点不到**。
- **发生环境**：Edge/Chrome × 360×780、390×844；影响 **登录页以外全部场景**（大厅 + 12 款游戏），共 394 次元素越界告警（mobile_s 139 + mobile 255）。平板(768)仅 1 次，桌面 0 次。
- **高频越界元素**：`#btn-share`、`#btn-leave-room`、`#btn-toggle-sound`、`#btn-toggle-theme`、`#btn-header-lobby`、`#display-time`、`#btn-toggle-players`、`#display-round-tag`、`#timer-box`。
- **复现步骤**：
  1. `npm start` 启动服务，浏览器访问 http://localhost:8080
  2. 开发者工具将视口设为 390×844（iPhone 尺寸）
  3. 输入昵称与房间号加入房间 → 观察顶栏右侧：「退出」「邀请」「音效」「主题」按钮消失或被裁切
  4. 房主开局任意游戏 → 顶栏「轮次」「计时器」同样溢出
- **影响**：移动端用户**无法退出房间、无法切换音效/主题、无法查看计时**，属核心交互功能失效。
- **截图证据**：
  - ![移动端大厅顶栏溢出](ui_audit_screens/Edge_mobile_lobby.png)
  - 对照正常桌面版：![桌面版顶栏](ui_audit_screens/Edge_desktop_lobby.png)
- **修复建议**：为 `.game-header` 增加移动端媒体查询——房间号 pill 设 `max-width` + 省略号；或 ≤480px 时隐藏/折叠次要按钮（音效、主题）进溢出菜单；`#display-round-tag` 等用 `flex-shrink` 允许压缩。

---

### 🟡 缺陷 2（Medium）：移动端大厅「邀请好友」按钮文字竖排堆叠

- **问题**：房主名 + 长房间号（如 `UI_Edge_mobile_s_6196`）挤压 `.hero-right-actions`，导致「邀请好友」按钮内文字**逐字竖排**（邀/请/好/友 各占一行），SVG 图标错位。
- **发生环境**：360×780、390×844 大厅场景。
- **复现步骤**：390px 视口 → 用较长昵称建房 → 查看大厅席位区右上「邀请好友」按钮。
- **截图证据**：![邀请按钮堆叠](ui_audit_screens/Edge_mobile_s_lobby.png)
- **修复建议**：`.hero-invite-btn` 设 `white-space:nowrap` + 窄屏下仅显示图标隐藏文字。

---

### 🟡 缺陷 3（Medium）：多处小字号低于可读阈值（<10px）

- **问题**：以下元素字号约 9.28px，移动端难以阅读：`div.quest-count`(35次)、`span.badge-seat-wait`(28)、`span.tile-badge.badge-party/action/puzzle`(各28)、`span.badge-seat-host`(7)、`div.seat-empty-label`(7)。
- **发生环境**：全部 5 个断点均出现（与分辨率无关，属固定小字号）。
- **复现步骤**：任意视口 → 大厅查看游戏磁贴右上角「经典/手速/益智」标签、席位卡「等待中」徽章。
- **截图证据**：![磁贴徽章](ui_audit_screens/Edge_mobile_lobby.png)
- **修复建议**：徽章类字号提升至 ≥10.5px（`font-size:0.66rem`→`0.72rem`）。

---

### 🟡 缺陷 4（Medium）：聊天展开按钮点击区过小（23×15px）

- **问题**：`#btn-toggle-chat`（「展开」按钮）尺寸仅 23×15px，远低于移动端推荐 44×44px 触控标准，易误触/点不中。`#cube-direct-input`、`#btn-hero-share` 亦偏小。
- **发生环境**：65 个场景，共 91 次告警（聊天栏常驻，全场景可见）。
- **复现步骤**：移动端视口 → 点击底部「房间聊天 展开」按钮。
- **修复建议**：为 `.btn-toggle-chat` 增加 `padding` 扩大点击热区（视觉尺寸不变）。

---

### ⚪ 缺陷 5（Low）：桌面版顶栏按钮文字轻微裁切

- **问题**：1920px 桌面版顶栏右侧「退出」「邀请」按钮文字被裁成「退」「邀」（图标+文字挤压）。
- **截图证据**：![桌面顶栏裁切](ui_audit_screens/Edge_desktop_lobby.png)（右上角）
- **修复建议**：同缺陷 1，调整 `.header-right` 间距。

---

### ⚪ 缺陷 6（Low）：登录页 favicon 404

- **问题**：`public/` 目录无 `favicon.ico`，浏览器自动请求 `/favicon.ico` 返回 404（登录页场景各 1 次）。
- **影响**：无功能影响，仅控制台噪音 + 标签页无图标。
- **修复建议**：放置 `public/favicon.ico` 或在 `index.html` 声明 `<link rel="icon">`。

## 四、误报说明（重要）

自动化脚本原始报告（`ui_audit_report.json`）含 **136 条 Critical「文字与背景几乎同色」+ 83 条 High「对比度不足」**，经复核 **全部为误报**，原因：

> 检测器通过 `getComputedStyle().backgroundColor` 读取背景色，但 PartyHub 大量使用 **CSS 渐变背景**（`linear-gradient` / `radial-gradient`，如主按钮 `.btn-arcade-enter`、UNO 卡牌 `.uno-card`）。渐变元素的 `backgroundColor` 计算值为 `rgba(0,0,0,0)`（透明），导致检测器向上取到深色祖先或白色兜底，误判对比度≈1.0。

**实证**：UNO 牌背黄色文字 `#FFD000` 在深红渐变 `radial-gradient(#FF6B8B,#C1121F)` 上**实际清晰可见**（见下方截图），但脚本判为「对比度 1.36 不可见」。

![UNO 黄字实际清晰](ui_audit_screens/Edge_mobile_s_uno.png)

> 结论：**不存在真实的文字不可见问题**。后续若需自动对比度检测，应改用「截图像素采样」或解析 `background-image` 渐变端点色。

## 七、环境限制声明

1. **浏览器内核**：本机仅 Edge/Chrome（均 Blink），未覆盖 Gecko/WebKit，跨内核渲染差异未检测。
2. **字体渲染**：headless 依赖本机 Segoe UI / 微软雅黑 / Segoe UI Emoji，与真机 iOS/Android 的 emoji、中文字重回退可能有细微差异，建议对 High 级截图做真机复核。
3. **沙箱退出码**：测试进程退出码为 1，系浏览器关闭时触碰系统缓存文件被沙箱拦截所致，**不影响审计结果完整性**（98 截图 + 报告均已正常生成）。
